# Convention evidence

Describe repeated repository behavior across a declared sample. Cover only applicable categories:

- naming and file layout;
- imports, exports, and dependency direction;
- request, response, event, or command shapes;
- validation and error propagation;
- configuration and environment variable access;
- constants, logging, tracing, and observability;
- test placement, fixtures, and assertion style;
- feature or package scaffolding.

Each convention records rule, category, example cites, sample size, counterexamples, confidence, and where a similar addition belongs. One instance is an example, not a convention. A repeated pattern with material exceptions names the boundary rather than hiding it.

This is descriptive guidance. Do not label divergence as bad practice or propose cleanup.
