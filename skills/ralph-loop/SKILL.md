# Ralph Loop

Use the caller-supplied `artifact_root` for every workflow-owned artifact. Stop if it is missing, outside the active repository, or escapes through a symlink. Product code stays in the approved repository paths, not the artifact folder.

This is a native, in-session execution protocol: a coordinator gives a fresh worker one approved task, checks the result, persists progress, then continues. It is not another planner, agent role, or verification framework.

## Inputs and continuity

Reuse the approved `tasks.md`, relevant specification/contracts, repository instructions, and existing `work/` briefs and reports. In Feature Pro, use `$FEATURE_ROOT`, `impl-spec.md`, and the relevant `erd.md` rows; preserve every Phase 9 gate.

For visual work, the brief carries the selected design artifact/reference, defining visual decisions, relevant tokens/components, realistic content/states and visual acceptance criteria. Workers inspect supplied references; missing material direction returns to the coordinator, not a fresh redesign. The coordinator retains design continuity across fresh contexts and owns browser comparison when workers lack that capability; provide captures without widening worker permissions. Keep a coherent screen or interaction in one task where practical, not separate styling tasks per widget. Establish the first representative render before visually dependent tasks when introducing a visual language; record the inspected reference, state/viewport, concrete differences and disposition in the existing report. Unrelated nonvisual tasks need no design exercise. Neither functional tests nor worker confidence prove visual acceptance; missing rendering follows the caller's explicit waiver/stop policy, not a silent pass. A caller may allow unaffected, dependency-ready nonvisual work while visual rendering is unavailable; this does not bypass that work's own prerequisites, authority or scheduling.

Keep `work/ledger.md` as the work record: task ID, attempt, status, owner, brief/report paths, proof/source reference, and next action or blocker. Record the finite budget once in its header. The coordinator alone updates shared progress, existing `skill_runs` and `agent_runs`, and the caller's trace. Reuse supported `agent-dispatched`, `agent-completed`, `retry-attempted`, and `gate-evaluated` events through the existing recorder; its failure policy still applies. Do not create a second plan, state schema, trace format, or output root. Do not record raw transcripts, secrets, or hidden reasoning.

## Execute, check, repeat

1. **Bound the work.** Default to two attempts per task and a total ceiling of twice the approved task count. If there are no pending tasks, reconcile completion without launching workers. Reserve and record an attempt before dispatch; failed, crashed, and interrupted attempts count. Do not reset counts on resume, compaction, `rebuild`, or task renaming. Splitting a task does not replenish its budget. Only explicit user approval can increase a finite budget; never use an unlimited mode.
2. **Select ready work.** `task-wave-execution` remains the sole scheduler. It selects dependency-ready tasks with disjoint write scopes, one task per worker, never two attempts for the same task concurrently. Reserve budgets serially before a parallel wave; obey the caller's concurrency cap. Thin vertical tasks remain valid; no mandatory layer swarm.
3. **Start fresh.** Use a new worker context for each task attempt. Do not fork the full conversation or reuse a previous worker's accumulated context. Pass the current canonical implementer definition, relevant skills, capability profile and supported adapter, explicit artifact root, bounded source/contract paths, allowed writes, acceptance checks, remaining budget, and previous failure report if any. Workers must read current files and preserve other workers' changes. A missing fresh-worker capability requires disclosure and an explicit user waiver before non-fresh fallback; never describe inline continuation as fresh. Same-or-stricter permissions remain required by caller policy; instructions are not a host-enforced sandbox.
4. **Implement one attempt.** Reuse local services/functions before inventing code or researching packages. For changed behavior, capture observed RED before implementation, then GREEN and safe refactoring; characterization tests must pass before a behavior-preserving refactor. Docs/config-only tasks use proportionate checks, not fabricated RED evidence. Follow approved test placement and task-specific gates. Use repository-native tests, lint, types, and build checks where applicable, never assumed package commands. One attempt is a bounded implementation/check pass, not an inner unlimited fix loop. Preserve unrelated edits; do not repair unrelated baseline failures.
5. **Verify before credit.** Workers return concise reports with commands, exit codes, relevant output, changed paths, current source identity, and unresolved issues. The coordinator must inspect the actual diff and referenced evidence. Run shared integration/build gates after all writers in the wave stop; dependent work cannot start before prerequisite checks pass. Neither worker success text nor a zero exit code substitutes for task acceptance and required evidence. Never mark a task done while a required check is failing, missing, stale, or blocked. Keep known baseline failures separate from new regressions and follow the caller's gate/waiver policy.
6. **Continue or stop.** Persist checked progress before dispatching the next ready task without routine approval. A failed task gets at most one further attempt within the budget, using fresh context and new failure evidence that supports a scoped correction. Otherwise stop with the failure and smallest next action; environment or authority failures stop immediately. Exhaustion pauses with remaining work, not a completion claim. Respect user pause; stop/settle active workers safely and reconcile partial writes. Do not dispatch more work while paused. Material scope, architecture, acceptance, or ownership changes return to the user rather than being rewritten to make the task pass.

## Resume and handoff

The coordinator retains the caller's phase presentation when defined; never invent phases for an unphased caller. A worker return within the same uninterrupted phase needs no new banner; task iterations are not workflow phases. On resume after interruption or compaction, restore the caller's entry banner and purpose when defined. When entering the next phase, show that phase's banner first; a loop summary or earlier preview does not replace it. This adds no state, gate or approval.

On resume, reconcile the ledger with current files and required checks; invalidate stale proof without discarding consumed attempts. An interrupted attempt remains incomplete until its writes and evidence are checked. Preserve partial work; do not reset, overwrite, or auto-commit it. Missing or inconsistent progress is an explicit reconciliation issue, not permission to invent completion or silently restart a budget.

Return completed tasks, remaining tasks, attempt counts, evidence paths, and any blocker in the existing report/ledger. This is task execution, not the completion of Feature Pro. Phase 9 still owns its seam checkpoint and exit decision; do not bypass later runtime, compression, review, QA, audit, or release gates.

No automatic staging, commits, pushes, PRs, deployments, dependency installation, or external writes are authorized by this skill. No background loop, shell runner, stop hook, or provider-specific CLI is required. Any such action needs the caller's normal explicit authority.
