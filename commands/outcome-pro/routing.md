# Outcome routing and ownership

Use the single canonical `outcome-analyst` agent (`agents/definitions/outcome-analyst.json`) with `analysis_focus: evidence | analysis | challenge`. These are distinct assignments, not three new permanent agents. Supply the current canonical definition, focus skill and applicable references by resolvable path or complete content; require reading before work, not reliance on registered snapshots. Load only relevant methods under Outcome authority; dependency build/release instructions grant no extra powers or gates.

| Focus | Primary skill | Trigger and return |
|---|---|---|
| evidence | `outcome-evidence-audit` | Nontrivial Phase 2 definitions, sources, exposure, maturity or conflicts; evidence fitness and gaps, never outcome verdict. |
| analysis | `outcome-analysis` | Substantive Phase 3; checked claims, calculations and options, never self-certified final verdict. |
| challenge | `outcome-independent-challenge` | Consequential or hard-to-reverse choice, conflicts, material segment/guardrail harm, causal/model assumptions; supported/disputed/unverified claims. |

A small uncontroversial question can use the selected skill inline. Do not launch analysis in an evidence-only run or dispatch all focuses automatically. Evidence → analysis → challenge has real dependencies. Parallel work is limited to independent bounded evidence slices; workers never dispatch workers.

For each material assignment use a new, fresh task context without inherited conversation, previous assessment, global memory or sibling history. Supply: explicit `artifact_root` even though no worker writes; focus; original question/decision and accepted intent; selected phase/method; approved evidence root and complete source manifest with exact locators/digests/read limits; cutoff; authority/privacy limits; accepted targets/guardrails/policies or explicit unknowns; contradictory evidence; expected return. Do not search unrelated inventories for missing context.

The analyst may receive an evidence audit, but must inspect original sources. The challenger receives original evidence and proposed claims only—not author rationale, confidence, desired verdict, inherited author context or previous worker reports. Supply the same complete approved source scope, including inconvenient evidence. A contaminated packet requires a clean fresh dispatch; do not pretend to forget it.

If the named agent is unavailable but fresh execution exists, a fresh generic worker can read the exact canonical definition and selected skill. Record that fallback, never claim installation. If fresh execution/files are unavailable, say **independent challenge not performed**, do bounded local checks, and mark consequential advice provisional. Inline checks are not independent review. Reconcile disagreement against original evidence, not votes; retain unresolved disagreement and narrow/withhold affected claims, especially harm.

Workers read only approved packet sources and linked instructions; permit deterministic read-only local arithmetic, but no network/production access, SQL execution, installs, writes (including worksheets), target changes or nested delegation. The coordinator alone owns collection, source reconciliation, artifact writes and final validation. Keep the canonical read-only capability profile binding. Distinguish host-enforced from instruction-only controls; missing native per-agent filtering is not a blanket gate, but missing explicitly required host isolation blocks that lane. These instructions are not a runtime sandbox guarantee.

In the existing proof note record actual runtime identity/focus, canonical methods delivered and read, source manifest/cutoff, calculation coverage and material challenge disposition. Labels or digests alone do not prove independent execution. Do not add schema fields or a new ledger; preserve clean challenger inputs and disclose unavailable expertise or independence.
