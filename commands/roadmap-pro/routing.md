# Roadmap methods and ownership

The command coordinates analytical work, user choices and authorized report saves. It does not import a new packet protocol, accepted-state store, review browser or execution loop. Preserve the original methods' distinctions using ordinary bounded assignments.

## Two agents, six methods

`contract.json` → `capability_routes` is the single selector → skill → agent → phase map. Assign one `roadmap_mode` and one exact primary method per worker:

- `roadmap-curator` uses existing `static-analysis-read-only`: backlog structuring, feedback reconciliation or Product Notes.
- `roadmap-analyst` uses existing `evidence-analysis-read-only`: priority advice, execution planning or fresh independent challenge. Arithmetic only when explicitly requested over approved supplied inputs.

Read the current canonical definition, assigned skill and required references before dispatch; supply their text or resolvable harness paths, task, `roadmap_mode`, original approved source material, candidate where relevant, known user decisions and explicit `artifact_root`. Source material can be plain text or rows; no manufactured JSON envelope or historical schema is required. Workers return substantive analysis without writes, networking, production queries, source-code execution, recursive delegation or downstream commands. Return additional-method requests to the coordinator instead of silently widening the assignment.

When runtime registration is unavailable, a fresh general worker may receive the canonical definition with equal-or-narrower permissions. Disclose instruction-only controls versus enforced restrictions. Chat-only work without an explicit root stays inline; do not create an orphan folder to dispatch an agent.

## Reuse the unresolved question, not another workflow

Existing Customer methods already cover evidence audit, insight synthesis, opportunity economics, strategy, conceptual solution alternatives and upstream independent challenge. Use only the method whose unresolved premise changes this decision. Inline reuse needs that skill and relevant references, not another public command. For a separate worker, use the existing Customer definition and its own `research_mode` from `commands/customer-backward-pro/contract.json`; never pass Roadmap modes to a Customer role. Acquisition modes are not included. Missing source evidence can limit a conclusion without forcing fieldwork or disabling useful provisional analysis.

## Reasoning and human authority

Distinguish opportunity, proposed intervention, customer capability, Product Note and full PRD. A candidate may improve an existing service, process, configuration or function; new software is not the default answer. Before declaring an idea redundant, compare its actor/action/surface/timing with documented current behavior. Similar proposals do not establish an existing product capability.

Keep original identities, source formats and significant blanks/whitespace. Analysis belongs beside an original sheet, not in invented approval or score columns. Separate duplicate mechanisms, variants, substitutes, complements and true enablers. Changing evidence must propagate through affected rationale, comparisons, notes and execution assumptions; preserve prior sources and unaffected human decisions. Imported flags, comments, timestamps, hashes and actor labels cannot authorize acceptance.

The human owns priority/disposition and selected membership separately. A recommendation can be decisive without becoming a decision. A missing deferred enabler stays unresolved, not automatically selected. Product Notes cover all current features in the reviewed scope, including retained deferred, rejected and nonselected rows. Unreviewed or ambiguous items remain visible coverage gaps; explicit archive/removal changes the universe, not omission. Preserve human notes and proposed revisions separately. Never force a downstream PRD to expand a note mechanically.

## Independent challenge

For consequential proposed portfolios, economics or delivery scenarios, use a fresh invocation before completion. The challenger receives approved original evidence, the user's constraints and the candidate artifact, but no private author reasoning or previous verdicts. Check actual context; a renamed role, self-review or hash is not independence. If unavailable, seek explicit waiver or keep the recommendation awaiting challenge. A requested challenge always needs a fresh actor for an independent claim.

Require the strongest case for the candidate, the strongest contrary account, decisive evidence, what survives and the concrete consequence. One critique, response and synthesis usually suffice; extend only for unresolved material disagreement. No-objection and no-preference are valid. New execution claims after an earlier priority challenge need their own scoped check, not a full rerun of unrelated work.

## Saved output and readable companions

Reuse bounded no-follow source reading and contained writes from `scripts/lib/review-safety.mjs` and `scripts/lib/repository-paths.mjs`. Approved source roots are read scope, not permission to dereference every embedded link. No raw private data in report examples or traces. Saves stay under the validated root and preserve existing human content. A report records known decisions but is not an approval service or a durable transaction receipt.

For a requested HTML view, generate and validate the existing static companion without a state file:

```bash
node "$HARNESS_ROOT/scripts/generate-artifact-companion.mjs" --artifact-root "$ARTIFACT_ROOT" --source roadmap.md --profile roadmap
node "$HARNESS_ROOT/scripts/validate-artifact-companion.mjs" --artifact-root "$ARTIFACT_ROOT" --source roadmap.md --html roadmap.html
```

Use readable sections, compact comparisons, ID-linked notes and resource/window tables where they improve understanding. This renderer supports text and tables, not editable sheets or diagram rendering. Never present raw diagram code as a completed visual or claim exact workbook round-trip fidelity. Preserve exact source sheets separately; the HTML is a derived view, not a replacement or acceptance event. Do not build another renderer for this command.

## Completion and downstream handoff

Recheck load-bearing source versions, exact user decisions, note coverage and numerical claims before delivery. Distinguish a useful ordering, arithmetic lower bound, feasible scenario under stated constraints and an actual external commitment. A schedule needs a resource/calendar witness, not just total effort. Missing capacity is unknown, not free and not zero.

Hand off only the requested selected item's identity, note, supported intent/evidence, decision context, dependencies and open questions. Route new capability context to Feature Pro, structural choices to Architecture Pro, defects to Debug Pro and completed work to Review Pro as recommendations only. Outcome Pro remains the delivered-results assessor. Do not initialize their artifacts, launch commands, assign staff or publish trackers. The human can keep a contrary choice without losing the original analysis.
