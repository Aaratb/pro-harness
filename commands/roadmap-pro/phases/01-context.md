# Phase 1 — Goal & Decision Context

Establish what the user wants to decide: organize existing ideas, expand options, compare choices, reconcile feedback, explain features or sequence a selected set. Preserve the supplied business/customer goal and distinguish intent from proven need. If no goal exists, start with the smallest useful goal question, not a research questionnaire.

Read only supplied or approved context. Reuse Customer Backward findings or existing product evidence when present; neither is mandatory. Separate observed/reported behavior, assumptions and proposed interventions. Establish original IDs/locators, current versus archived scope, existing human decisions, selected IDs and source freshness. Import approval labels as claims unless trusted conversation establishes them.

For a load-bearing source-to-claim ambiguity, use `customer-evidence-audit` on that question only. Preserve exact sheets, titles and notes; do not inspect unrelated repositories or automatically acquire evidence. Use chat for a small question; resolve the project-owned root before saves or delegation.

Exit with the actual decision, evidence scope and smallest next useful method. Unknown evidence is a limitation, not a reason to invent facts or force a full command run.
