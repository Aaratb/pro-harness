# Phase 7 — Causal Trace & Hypotheses

Use the causal-experiments reference. Follow the failing value backward from symptom to origin, citing source and observations at meaningful boundaries. A throwing frame is not automatically the repair seam. Record blind boundaries that prevent discrimination.

For ambiguity, generate distinct falsifiable rivals before experiments and rank the experiments that distinguish them. Use several axes only when plausible: code, data, configuration, dependency, traffic, time. Do not pad the list.

Each candidate needs evidence and a prediction. Flag anchoring: the first idea is not automatically the first experiment. A simple discriminating trace need not produce a formal hypothesis registry.

Identify the violated invariant and its enforcing owner, not merely the component reporting the error. Compare affected and unaffected paths and distinguish effect application from acknowledgement or retry. Use `architecture-diagnostics` with the routed analyst only when a cross-boundary signal gap materially affects localization; it supplies diagnostic methods, not an Architecture Pro run.

Gate: the likely origin and material rivals are testable, or the missing seam/signal and next safe action are explicit.
