## Additional phase requirements

- **Every task declares its interfaces.** Per task record `Consumes:` (types/contracts/endpoints/events it needs, each either already existing or produced by a named earlier task) and `Produces:` (what it makes available). A task whose `Consumes` names nothing that `Produces` it is an ordering defect — catch it here, not mid-build.
- **No placeholders in a plan.** `TODO`, `similar to the above`, `handle errors appropriately`, an unresolved library choice, or a step with no expected output are plan failures, not implementer discretion.
- **Classify every decision** — **Mechanical** (one defensible answer; resolve and cite the forcing constraint) · **Taste** (several defensible; resolve, name the tiebreaker, record the runner-up) · **User Challenge** (changes what the feature is for, or contradicts a stated direction — **never auto-resolved**; your stated direction is the default and the model must argue for change with evidence).
- **"No issues found" requires what was examined.** "Skipped" is never valid.
- For any API/CLI/SDK/agent-facing surface, add the **interface-ergonomics pass**: describe what a 10/10 would look like for this product, say where the plan sits, name the gap, and set a time-to-hello-world target as a number. Raise each friction point as its own checkpoint item — batching them into one "UX concerns" bullet reliably gets it waved through.
