# Phase 2 — Orient

Give a first-time reader a reliable map and an efficient reading sequence.

## Required work

1. Build a plain-language product overview from manifests, entry points, checked-in documentation, and tests. Separate verified purpose from inference.
2. Classify significant files by why a learner would open them: start-here, business rules, entry points, data, supporting, infrastructure, or generated/vendor. This is a workflow-local learning classification, not a harness folder taxonomy.
3. Produce the `start with these files` shortlist from fan-in, entry-point, rule, and boundary evidence. Count the scoped corpus rather than using an unsupported percentage claim.
4. Explain how the project is intended to be run from cited repository instructions, prerequisites, configuration variable names, and success signals. Do not execute it.
5. Derive a dependency-aware reading plan from the intake graph. The ordering is an explained inference; entry points and import edges are cited facts.
6. Seed the living glossary at first use.

Show the next useful question each starting file answers and how it connects to the running example. Rank for this learner's path, not centrality alone. Include the phase's short prediction and its resolution in the course; do not pause for an answer or claim the reader has already understood it.

## Artifacts

- `sections/repo-atlas.json`
- `sections/reading-plan.json`
- updated `registry.json` and `claims.json`

## Gate

A fresh repository-explorer pass checks every shortlisted file, material count, entry point, and cited dependency. The phase passes when a reader knows what the repository does, where to begin, what to ignore initially, and why the reading order works.
